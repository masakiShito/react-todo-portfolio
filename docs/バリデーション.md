# バリデーション設計（Todoアプリ）

最終更新: 2025-12-09

## 対象フィールド

- タイトル（必須）
- 説明（任意）
- 優先度（必須: 高/中/低）
- タグ（必須: 開発/レビュー/MTG/その他）
- 期限（任意: datetime-local）

## ルール定義

### タイトル

- 必須入力: 空文字・空白のみを禁止（送信前に`trim`）
- 長さ: 1〜100文字（推奨）
- 重複禁止: 既存タスクと同一タイトルを禁止（大小文字差、前後空白を無視して比較）

### 説明

- 任意入力
- 長さ: 最大1000文字（推奨）

### 優先度

- 許容値のみ: `"高" | "中" | "低"`

### タグ

- 許容値のみ: `"開発" | "レビュー" | "MTG" | "その他"`

### 期限

- 形式: `datetime-local`の有効フォーマット
- 妥当性: 過去日時を禁止（現在時刻より未来または同時刻以上のみ許可）

## 入力前処理（正規化）

- 全フィールド`trim`（タイトル/説明）
- 期限は`new Date(value)`でISO文字列へ正規化（タイムゾーン差異に注意）

## エラー表示仕様

- フィールド単位でメッセージ表示
- ARIA対応
  - `aria-invalid="true"`（エラー時）
  - `aria-describedby`でエラー文を関連付け
- メッセージ例
  - タイトル: 「タイトルは必須です」「100文字以内で入力してください」「同じタイトルが既に存在します」
  - 期限: 「過去の日時は設定できません」

## フロー（擬似コード）

```ts
function validateTask(input: TaskInput, existing: Task[]): ValidationResult {
  const errors: Record<string, string> = {};

  const title = input.title.trim();
  const desc = (input.description ?? '').trim();

  if (!title) errors.title = 'タイトルは必須です';
  if (title.length > 100) errors.title = '100文字以内で入力してください';
  const normalizedTitle = title.toLowerCase();
  const isDup = existing.some(t => t.title.trim().toLowerCase() === normalizedTitle);
  if (isDup) errors.title = '同じタイトルが既に存在します';

  if (desc.length > 1000) errors.description = '1000文字以内で入力してください';

  if (!['高','中','低'].includes(input.priority)) errors.priority = '優先度が不正です';
  if (!['開発','レビュー','MTG','その他'].includes(input.tag)) errors.tag = 'タグが不正です';

  if (input.dueDate) {
    const d = new Date(input.dueDate);
    if (isNaN(d.getTime())) errors.dueDate = '期限の形式が不正です';
    else if (d.getTime() < Date.now()) errors.dueDate = '過去の日時は設定できません';
  }

  return { valid: Object.keys(errors).length === 0, errors };
}
```

## 実装ポイント

- フロント送信前に検証（`TodoInput`内で実施）
- 追加/編集共通のバリデーション関数を`utils/validation.ts`へ切り出し（再利用）
- 失敗時は追加/更新を行わず、メッセージを表示
- ローカルストレージ書き込み前にも最終チェック（防御的）

## テスト方針

- 正常系: 各フィールド境界値（文字数1/100、説明999/1000など）
- 異常系: 空タイトル、重複タイトル、期限の過去日時、許容外の優先度/タグ
- フォーカス/ARIA: エラー時に`aria-invalid`と`aria-describedby`が適用されること

## 組み込み手順（実装）

1. `utils/validation.ts`の`validateTask`をインポート
2. 追加時（`TodoInput.tsx`）
   - 送信ハンドラで入力値を`TaskInput`へ整形（`trim`）
   - 既存タスク配列を渡して`validateTask`実行
   - `valid=false`ならメッセージ表示＋`aria-invalid`/`aria-describedby`設定、追加中断
3. 編集時（`TodoItem.tsx`）
   - 保存ハンドラで編集値を`TaskInput`へ整形
   - 自タスクを重複判定から除外して`validateTask`実行
   - 失敗なら編集モード継続＋エラーメッセージ表示
4. UI反映
   - エラーのあるフィールド: 枠線色/フォーカスリングをアクセント＋赤系に切替（任意）
   - 送信/保存ボタンは`disabled`制御（任意）

### 例（疑似コード: TodoInput）

```tsx
import { validateTask } from '../utils/validation';

const handleSubmit = () => {
  const input = {
    title: title.trim(),
    description: description.trim(),
    priority,
    tag,
    dueDate,
  };
  const { valid, errors } = validateTask(input, tasks);
  setFormErrors(errors);
  if (!valid) return;
  // 追加処理...
};
```

### 重複判定（編集時）

```ts
const existingForEdit = tasks.filter(t => t.id !== task.id);
const { valid, errors } = validateTask(input, existingForEdit);
```

## エラーメッセージ仕様（詳細）

- 表示位置: フィールド直下（小さめのテキスト）
- 文言優先度: 必須 > 長さ > 重複 の順で1件を表示（複数同時表示は避ける）
- 国際化: 文言はi18n対応可能な形で外部化（任意）

## パフォーマンス/UX考慮

- 入力中のリアルタイム検証はタイトル長/必須のみ（残りは送信時）
- 期限の過去判定は送信時に実施（タイムゾーン誤差を避ける）
- 成功時はフォームリセット、失敗時は値保持
